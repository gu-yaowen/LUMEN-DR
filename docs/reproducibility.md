# Reproducibility guide

This guide separates files needed to understand or rerun LUMEN-DR from files
that are generated during experiments. All commands below are intended to run
from the repository root.

## 1. Environment

Use Python 3.10 or newer. Install the main package with:

```bash
python -m pip install -e .
```

Install a PyTorch build matching the available CUDA runtime before installing
the package if the default wheel is not appropriate. The model uses PyTorch
Geometric; its installation should match the installed PyTorch build.

The optional baseline environment is separate because MRDDA, AdaDR, and AutoDR
were released with different dependency versions. The baseline dependency
specification is in `baselines/requirements.txt`.

## 2. Released data

The final normalized inputs are in `data/`:

```text
data/<DATASET>/
├── drug.csv
├── disease.csv
├── protein.csv
├── drug_dis.csv
├── drug_protein.csv
├── protein_disease.csv
└── protein_protein.csv
```

`Bdataset`, `Cdataset`, and `Fdataset` use contiguous integer indices. The
provenance and normalization rules are recorded in
[`data/dataset_process.md`](../data/dataset_process.md).

## 3. Feature caches

Training requires three frozen embedding dictionaries for each dataset:

```text
features/<DATASET>/MolFormer_drug_emb.pkl
features/<DATASET>/BERT_disease_emb.pkl
features/<DATASET>/ESMC_protein_emb.pkl
```

These files are not included because they are large generated artifacts. The
released code loads them using `src/lmdda/utils/features.py`, but this release
does not include the historical feature-generation script. To reproduce the
reported runs, regenerate the files with the same model checkpoints,
preprocessing text, sequence handling, pooling rule, and entity IDs described
in `data/dataset_process.md`. Do not mix embedding files from a different
dataset normalization revision.

## 4. Standard training

The package exposes one entry point for training, prediction, and embedding
export:

```bash
python -m lmdda --mode train \
  --dataset Bdataset \
  --data-root data \
  --features-root features \
  --output-root outputs \
  --run-name final_bdataset \
  --device cuda:0
```

The defaults are intentionally repository-relative. Use explicit arguments in
batch jobs so that the run configuration is self-documenting. A short shell
wrapper is provided at `scripts/run_cv.sh`.

Each run stores its configuration, checkpoint, per-fold metrics, predictions,
and logs below `outputs/`. These generated files are ignored by Git.

## 5. Cold-start evaluation

The main package supports `--split-mode cold_drug` and
`--split-mode cold_disease`. The cold-start protocol description retained in
`baselines/cold_start_splits/cold_start_reproduction_protocol.md` defines the
entity-level evaluation convention.

The archived `baselines/shared_splits/` files were intentionally removed. As a
result, exact cross-model comparison requires regenerating the shared pair-level
and cold-start split files locally and recording their seeds and checksums in
the run directory before executing the baseline code.

## 6. Baselines

Baseline source code is retained under `baselines/MRDDA`, `baselines/AdaDR`, and
`baselines/AutoDR`. The baseline README describes their historical dependency
requirements and entry points. Archived baseline result JSON files were removed
from this repository; no reported metric should be treated as reproducible from
this checkout alone without rerunning the models.

## 7. What is intentionally excluded

The following are generated or archival artifacts and are not part of the
public release:

- `features/` embedding caches;
- `outputs/`, `logs/`, and `reports/` generated run artifacts;
- `results/figures/` paper figures and plotted CSV files;
- archived baseline result JSON files;
- `baselines/shared_splits/` pair-level shared split archives;
- local cluster images, overlay files, and scheduler logs.

This omission keeps the repository focused on source code and final input data;
it also avoids presenting historical outputs as if they were generated by a
fresh checkout.
